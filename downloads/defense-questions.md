## 高频问题及回答要点

### 1. 为什么一个插件也算期末工程？

课程 PDF 第 4 页允许为开源 Agent 环境开发插件，第 7 页明确列出 DeepSeek Harness 插件研究与开发。交付不是仅有提示词，而是生命周期接线、持久存储、作用域治理、工具、安装和评测。规模不是由代码行数或插件个数证明。

### 2. “记忆”是不是把对话再发给模型？训练了模型吗？

没有训练或更新模型权重。把历史对话中的长期信息抽取为结构化记录，后续检索部分记录注入上下文；回答仍由宿主配置的模型生成。它是外部持久记忆，不是模型参数记忆。

### 3. 与 AGENTS.md 有什么区别，为什么不用文件？

文件简单、便宜、可审阅，对稳定规则很适合。插件的价值是自动维护变化、保留退役记录并提供管理入口。本实验只证明相对冻结文件的部分收益，持续人工维护的文件可能同样答对，其时间成本还没测。

### 4. 创新在哪里？

工程贡献是把原生事件、按项目持久化、冲突替代和审批准入整合为可安装插件，并用对照实验呈现收益与代价。衰减、检索、记忆本身不是新发明，不宣称提出了新的基础算法。

### 5. 为什么不用 MCP？

本课题聚焦宿主原生插件，可直接使用事件、模型路由和存储，减少另行维护进程与协议的工作。代价是依赖 dsh 的具体 API。没有测量 MCP 与原生插件的性能差异，所以不声称原生一定更快或全面优越。

### 6. 为什么轮末抽取而不是退出时抽取？

实测 headless 进程退出太快，session/disposed 来不及完成。agent/turn-stopping 可等待，因此作为主路径；代价是轮末会等待辅助模型调用。退出事件只做兜底，不承诺任何异常退出都不会丢失增量。

### 7. 冲突消解如何避免把新旧事实都删掉？

先识别旧记录并把它排除出本次去重池，再写新记录；写成功后才退役旧记录。审批模式下同批替代候选全部存在并获准，才退役旧事实。不能沿用早期“先退役再写入”的简化描述。源码：index.ts 的 settle，store.ts 的 merge/approve。

### 8. 为什么某条旧规则重新生效时不会被误判为重复？

已退役条目不参与去重，恢复的规则建立新的有效记录。保留退役历史便于审阅；不是简单覆盖一个文本字段。

### 9. 半衰期 14/30/45 天有什么科学依据？

是当前工程启发式：事实变化较快、偏好较稳定。尚未用真实长期数据拟合这些数值，也没有因果证明它们最优。普通记忆有效置信度按指数衰减，低于 0.15 不注入。新版允许用户指定持久记忆，不因时间流逝被过滤；并不保证每次召回。具体天数仍需消融与长期使用校准。

### 10. “语义去重”用了向量数据库吗？

没有。模型抽取时对已有记录做语义对齐，存储层再用规范化精确匹配和词项包含度 0.65 兜底；中文使用字二元组。注入排序也是词项重合与有效置信度，不是 embedding 余弦相似度。中文改写和阈值仍可能失误。

### 11. 置信度是概率吗？重复怎么强化？

不是校准概率，数值可大于 1，上限 2。merge 重复合并加 0.1，显式 reinforce 加 0.15，注入命中加 0.02 且 60 秒去抖。不要把这些不同路径混为一个数。

### 12. memory_approve 能防止提示注入吗？

只能缓解。自动候选可先保持不可见，但审批工具仍由模型调用，显式 extract 也会直接批准；不构成人类身份验证或安全沙箱。注入声明、来源和删除可降低管理成本，无法保证恶意内容绝不生效。

### 13. 工作区隔离是不是绝对的？

管理工具和注入访问当前工作区加全局记录，自动抽取只修改当前工作区；全局记忆是有意共享。子 Agent 和缺少会话的工具调用被拒绝。没有宣称它能抵御有文件权限的恶意本机进程。

### 14. 有来源编号是否证明事实真实？

不能。编号定位一条存储记录，记录另存 sourceSessionId；显示日期可能是最近强化日期。模型可能误述来源，历史事实也可能已过期。历史视频曾保留模型把条目称为会话的措辞错误，新版按实际记录引用编号，不能把引用有效率等同事实准确率。

### 15. 100% 是不是题目太简单、答案泄漏？

案例确实是预先固定的合成短场景，覆盖面有限。答案表不进入模型输入，按冻结问题和评分执行；但无独立留出集，不能据此排除设计偏差。最强证据是本组案例可复现，以及差异集中于旧约定更新。

### 16. 三次重复是否说明统计显著？

没有做显著性结论。只有 20 个不同主案例，三次重复是相同案例的稳定性观察，不能当成 60 个独立任务。主单元 180，加独立诊断 12，总计 192。

### 17. 无插件 25% 是幻觉很多吗？

不是。它全部回答 UNKNOWN，其中 15 次符合预期的无依据拒答，45 次因缺历史不能完成任务。三组在预期 UNKNOWN 的主案例都没有无依据回答，不能拿这个结果宣传减少了已观测到的幻觉率。

### 18. 5.73 倍为什么还值得用？花了多少钱？

本实验没有账单金额，只记录 usage。59,949/10,455 为主实验 token 比，包含 99 次历史抽取；正式全部 306 次请求共 89,057 tokens。是否值得依赖规则变更频率和维护成本，尚不能普遍下结论。演示新增调用另算，不混入正式实验。

### 19. 58+7 和 19 分别测试什么？

58 是主插件存储、解析、工具和生命周期回归，7 是副插件纯函数，19 是评测器预算、评分、日志与异常处理等自检。真实宿主固定输出验证、真实模型受控实验、真实网页演示是另外三层证据，不能把它们混称一套完整生产端到端测试。

### 20. 为什么插件最初本地能跑，安装却会失败？

源码 Git 包没有 dist，而安装器依赖 prepare 构建。开发机预先构建和 junction 掩盖了依赖问题。修复 prepare 和 peer 后，CI 增加干净 Git 安装检查，证明提交的代码可以在新环境生成入口。dsh 管理器还可能要求显式 allowBuilds。

### 21. 删除后还会记住吗？演示为什么改了自动阈值？

forget 删除存储记录，但不是禁止以后重新学习同一事实。如果当前会话再次出现这条信息，自动抽取可能重新保存。历史 v0.4.1 删除演示使用较高自动抽取阈值，不代表永久屏蔽重学。新版 v0.5.1 网页演示保持默认自动抽取，展示的是取消持久保留而非删除；内容仍在。默认自动配置为 120 字/90 秒。

### 22. AI 做了这么多，你做了什么？

按实际分工回答：我确认选题范围和执行优先级、配置凭证、运行真实评测、审阅产品和展示方向，并负责理解、最终提交与答辩。AI 做研究实现、测试脚本、复核与材料生成。不虚构手写贡献；接着选一个真正理解的失败案例解释如何定位、为什么修复有效。

### 23. 视频有没有伪造输出？为什么不是原生终端窗口？

新版直接操作真实 dsh 官方网页，Chrome 捕获实际视口；不是自制终端输出页。未改写网页回答或工具结果，字幕、右侧鲸鱼和说明为后期引导。安装使用本地已构建包，等待有剪辑；会话、时间索引和存储快照可复核。

### 24. 如果继续做，你会先改什么？

先扩充独立真实项目任务、加入持续维护的静态基线及人工复核，再测默认配置下的长期调用成本。产品上优先解决删除后的重学策略、退出后的重试和独立授权边界；embedding 与 npm 发布属于后续选择，不因为容易展示就先堆功能。

### 25. 持久记忆是否永远有效？如何取消？

不保证永远正确，只豁免时间衰减。用户指定 memory_pin(id, true)，取消传 false；需要已批准、未退役的唯一条目。取消按原时间恢复，可能立即停止注入；重复合并保留标记，新替代记录不继承。仍可删除或被替代，仍受相关性与容量限制。180/365 天模拟与真实后端重启证明程序行为，不证明长期实际准确率。旧 60/60 来自 v0.4.1。

### 26. 为什么安装前的空会话曾经记不住？

插件原来只监听 agent/created。空会话已经存在，安装后复用不会重发创建事件。v0.5.1 先监听再遍历现有 Agent 补挂，按对象去重；卸载清理提示段并关闭存储域。58 项回归、真实宿主热加载/重载与真实网页注入均有证据。
