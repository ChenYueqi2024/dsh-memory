八项核心能力

自动沉淀

轮末在增量和间隔达标时，用辅助 LLM 调用抽取决策、约定、偏好、事实；默认最小间隔 90 秒。

语义去重

模型语义对齐与词项包含度兜底协作；本组 12 次同义重述均强化原记录，没有重复新增。

工作区隔离

注入与工具操作限定当前项目及全局记录；自动抽取只修改当前项目。

相关性注入

新会话按有效置信度 + 关键词重合度排序注入 Top-N，拒绝无脑全量灌上下文。

用户指定持久记忆

memory_pin 设置或取消持久保留。普通记忆半衰期为 fact 14 天、decision / convention 30 天、preference 45 天；持久记忆不参与时间衰减，仍可替代和删除。

来源可解释

每条记忆带条目编号与最近创建或强化日期；存储中保留初始会话编号，错了可用 memory_forget 删除。

冲突消解

新事实先写入，旧事实再退役留档；待审批替代项整批获准后才退役旧规则。识别效果仍依赖模型。

审批准入

requireApproval 开启后，自动候选经 memory_approve 批准才注入；冲突旧事实在替代项批准后退役。审批工具可由模型调用。

如何理解这些数字
  • 仅限固定合成案例，60 次作答不是 60 个独立案例，没有独立留出集或显著性结论。
  • 未比较持续人工维护的 AGENTS.md；本次是受控上下文实验，非完整 CLI/Web/TUI 任务评测。
  • 长会话、真实代码任务、时间衰减和复杂攻击未覆盖。实验 1 字/0 秒触发设置不代表默认 120 字/90 秒成本。
  • AI 对照历史审阅 96 条新增候选，未发现无支持事实；未做独立人工标注，不等于普遍零污染。

架构：四个官方扩展点的组合

沉淀session/event 积累对话文本 → agent/turn-stopping 轮末触发抽取（headless 退出时 session/disposed 兜底不能保证完成）
抽取ctx.llm.stream() 辅助调用输出 JSON 候选，会增加调用量与轮末等待
存储ctx.storageDomain 官方存储域 dsh_memory，per-record JSON 后端，零自建依赖
注入agent/created 时挂 systemPrompt.section()，按当前问题动态求值
管理ctx.tools.register() 暴露五个工具：memory_list / memory_forget / memory_extract / memory_approve / memory_pin

长期约定由用户指定保留

告诉 Agent：“把‘项目统一使用 pnpm’设为持久记忆。”先保存并查看条目，再调用 memory_pin({id, pinned: true})；取消使用 false。自动抽取不决定持久标记，只能设置已批准、未退役的条目。

取消后按原时间恢复衰减，可能立即停止注入。重复合并保留标记，新规则替代不继承；持久记忆仍受工作区、相关性和上下文容量限制，并不保证每次注入。工具由 Agent 调用，不是独立人类认证。

新增验证：模拟 180/365 天，真实 JSON 后端跨四次启动，旧 schema v1–v5 兼容与干净 Git 安装。无新增真实模型请求，不改动原 60/60、306 请求和成本统计；这些测试不能证明长期实际准确率或 14/30/45 天最优。
